# HG002 analysis data dictionary — schema 1.0

All HG002 results refer only to GRCh38 chr9:128,000,001–129,000,000. Teaching validation teaching variants are separate. An allele is identified by normalized `chromosome:position:REF:ALT`, not position alone. TSV fields are tab-separated; lists use semicolons unless explicitly JSON. Empty optional fields mean not reported. No clinical classification is generated by this project.

## Inputs and interval membership

The fixed inputs are GIAB HG002 NIST v4.2.1 GRCh38 benchmark VCF and matching `benchmark_noinconsistent.bed`. VCF positions are 1-based. BED and JSON bin boundaries use 0-based half-open intervals. Entire anchored REF spans `[POS-1, POS-1+len(REF))` must fit inside both the analyzed interval and a single merged high-confidence region before and after normalization. Insertions use the anchored VCF reference base. Alleles shifted outside this rule are excluded explicitly. Bin assignment uses normalized VCF anchor position.

Eligible variants have PASS or unspecified FILTER, a non-reference ALT present in the sample genotype, only A/C/G/T sequence, differing REF/ALT, and REF and ALT lengths no greater than 50 bases. Multiallelic records are split manually with original allele indexes retained, then normalized using bcftools 1.21. MNVs would remain MNVs rather than being atomized. Chromosome `chr9` is reconciled to reference/Ensembl `9`. Every included full REF interval is checked against the matching GRCh38 chromosome sequence.

## Main exports

### `allele-summary.tsv`

One row per deduplicated normalized allele. `allele_id`, chromosome, position, REF, ALT and variant type identify the call. Variant type is SNV for single-base substitutions, indel when lengths differ, and MNV otherwise. `provider_most_severe` is VEP's overall most-severe label across all reported features. `transcript_rows` counts transcript annotations; `genes` and `transcript_terms` summarize their distinct values. `clinvar_status` distinguishes exact eligible release matches from unmatched alleles.

### `transcripts.tsv`

One row per reported allele–transcript annotation. `row_id` combines the allele ID with a deterministic ordinal after sorting by gene, transcript and annotation content. Rows retain gene symbol/ID, transcript accession/version, biotype, consequence terms, most-severe transcript term, MANE Select, canonical flag, HGVSc, HGVSp and returned variant allele. A missing MANE annotation means no flag was reported, not that the gene has no MANE transcript. Versions are extracted from a versioned accession if a separate version field is absent.

### `transcript-selection.tsv`

One row per allele–gene pair with at least one transcript row. Representative selection prioritizes MANE Select, canonical, then transcript accession and row ID. `selection_ties` counts candidates at the preferred reporting tier; canonical status and accession resolve ties deterministically. `different_across_transcripts` compares consequence term sets, regardless of term order. `selected_misses_more_severe` is 1 when another same-gene transcript has a term ranked above the selected transcript's most-severe term. This measures annotation sensitivity, not clinical importance.

The ranking is pinned to Ensembl release 116 `ensembl-variation` Constants.pm, retained under `docs/`. Unknown terms fail analysis rather than receiving an invented rank.

### `consequence-spectrum.tsv` and `transcript-term-counts.tsv`

The spectrum has distinct `alleles` and `transcript_rows` units. Each allele contributes once to its provider severity summary; each transcript row contributes once to its most-severe transcript term. Allele counts are broken down by SNV/indel/MNV where observed. `denominator` is all items in that unit; `type_denominator` is all items in that variant type. Transcript unit type is `all`.

The separate term-count table counts a transcript row once for every reported term. These categories overlap and must not be added to infer the number of transcript rows or alleles.

### `gene-summary.tsv`

Per-gene distinct allele counts, transcript rows and transcript-sensitivity pair counts. An allele can affect multiple genes, so gene totals can exceed the number of alleles.

### `bins.tsv`

Forty fixed 25 kb bins. Each row contains the bin ID, 0-based start and exclusive end, distinct allele count, clipped/merged high-confidence BED coverage in bases, alleles per million high-confidence bases and JSON consequence counts. A bin with zero coverage has no rate; it must not be interpreted as evidence of no variation. Densities are descriptive benchmark-sample measures, not population frequencies or disease hotspots.

Explorer filters change the allele numerator. The displayed denominator remains the full bin's high-confidence coverage even when a position filter cuts through that bin. The analyzed boundary is fixed; filters cannot extend it.

### `origin-map.tsv`, `original-region.vcf`, `normalized.vcf`, `exclusions.tsv`

Original VCF records retain source IDs, FORMAT and sample fields. Origin mappings retain each original ALT index and original chromosome/position/alleles for every normalized allele. Deduplication merges only identical normalized chromosome/position/REF/ALT identities and preserves every origin. Exclusions include original records and explicit reasons. Normalized VCF is annotation input, rather than a clinical sample export preserving all original FORMAT annotations.

### `other-features.json`

Non-transcript feature annotations, labelled by provider feature category. These never enter transcript counts.

### `clinvar-matches.tsv` and `clinvar-overlay.json`

Exact normalized allele matches to the ClinVar GRCh38 release dated 2026-11-08. The full chromosome 9 regional extract was obtained by index, and eligible ACGT alleles up to 50 bases were reference-checked and normalized with the same bcftools/reference as HG002. No coordinate-only match is accepted. The acquired chromosome 9 records are all biallelic; original ALT indexes are nevertheless retained during normalization.

Records preserve Variation ID, source classification summary (`CLNSIG`), review status (`CLNREVSTAT`), condition names/identifiers, conflicting classification details, somatic impact/oncogenicity fields where present, source URL and original VCF record. Raw INFO remains available in the original record, including fields not promoted into a separate column. Strings retain source spellings/encodings rather than being reclassified.

“No exact eligible match in this release” means no matching normalized small-allele entry in the fixed extract; it does not mean benign, absent from every ClinVar representation, or absent from a newer release. Review status is not a project endorsement. Unmatched and unsupported-source counts remain explicit.

### `cases.json`

Four observed HG002 examples selected deterministically to illustrate a coding SNV, an indel, transcript sensitivity and missing HGVS evidence. Each includes selected and available alternative same-gene transcript rows, selection rationale, source raw chunk, and exact ClinVar assertions when matched. A source row can be recovered from the full transcript TSV by `row_id`.

### Manifests and metrics

`results/snapshot.json` identifies the successful VEP chunk set, exact options, reference/input fingerprint, acquired timestamps and immutable snapshot inputs. `results/run-manifest.json` combines annotation provenance with the later ClinVar overlay. Clinical overlay status in the original annotation-stage scope predates the successful overlay; the combined manifest and exports report its actual availability.

`export-manifest.json` hashes the final analytical exports. `metrics.json` records denominators and missing optional fields. `no_transcript_alleles` counts valid VEP objects without transcript overlap; `unannotated_alleles` counts inputs without a VEP result. The pipeline requires complete response coverage for snapshot promotion.

`report-dataset.json` is the compact overview dataset. All transcript detail is in separate local per-allele JSON assets, loaded only after selection. Report rendering uses the recorded acquisition time and never inserts a new clock time.

## Display-only consequence classes

The 3D Y axis groups the provider most-severe term into a single class per allele. Exact terms remain unchanged in exports, filters and case evidence. `consequence_class` is exported with every allele; `term_classes` in the compact dataset supplies the full mapping. The groups are:

| Class | Source terms |
| --- | --- |
| Truncating / lost | transcript_ablation, stop_gained, frameshift_variant, stop_lost, start_lost |
| Splice related | Terms beginning `splice_` |
| Other coding | missense, synonymous, in-frame insertion/deletion, protein_altering, coding_sequence, retained start/stop and incomplete terminal codon terms |
| UTR | 5_prime_UTR_variant and 3_prime_UTR_variant |
| Flanking gene | upstream_gene_variant and downstream_gene_variant |
| Intergenic | intergenic_variant |
| Regulatory / motif | Regulatory and TF-related terms |
| Other transcript | Remaining recognized terms, including intron and noncoding transcript terms |

These are visualization groups, not clinical impact categories. Class counts in a bin sum to that bin's distinct allele count. The exact selected-bin class table provides a keyboard-accessible equivalent to the 3D bars. The square-root count scale transforms only bar height; labels and counts retain original allele units.

Case selection prefers an observed missense SNV with an exact clinical-source match, a coding indel when available, a transcript-sensitive pair missing a highly ranked alternative term, and a separate case with missing representative HGVS. Choices illustrate evidence and missingness; they do not change full-run totals or imply representative clinical prevalence.

## Explorer filters and presentation

The default is a fixed-scale 2D position/count chart; 3D is optional and loaded on request. Type and provider-summary consequence filters apply on change. Gene text matches case-insensitive substrings of source symbols/IDs and updates after a short debounce. Region changes apply when committed. Multiple active filters are combined with AND. The status panel explains the displayed subset and excluded count. A valid allele with zero transcript rows remains selectable and is explicitly explained as having no reported transcript overlap.

The shareable experiment report is a separate, self-contained interpretation of saved results, not a new annotation run. Its three scientific figures use the existing allele, transcript-selection and bin exports. The result hashes and scope remain those of the original completed pilot.
