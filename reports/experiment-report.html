Executive summary

This project investigates a practical problem in variant annotation: the same DNA change can receive different predicted effects when interpreted against different transcripts of a gene. A transcript is an RNA version produced from a gene. Different versions can use different exons, coding boundaries or splice sites, so the location and predicted effect of one variant can change with the transcript model.

The work began with five public Ensembl training examples and expanded to a preselected one-million-base interval from HG002, a public benchmark sample. Existing variant calls were checked against GRCh38, normalized, annotated using genuine Ensembl VEP results, analyzed across all reported transcripts, and presented in reproducible exports and local reports.

1. Purpose and scientific question

Research question: how do predicted consequences differ across transcripts, and what evidence would be needed to assess clinical significance?

The experiment does not begin with sequencing reads. It begins with already-called variants: a teaching set in Training validation and an established public benchmark callset in HG002 analysis. The task is to annotate and compare those supplied calls. No variant-calling accuracy, precision or recall is estimated because there is no independent query callset being benchmarked against truth.

The objective is both analytical and practical: preserve an auditable route from input allele to raw annotation, transcript-level export, representative-transcript decision and the explanation presented to a reader. Every numerical headline can be reconciled with saved exports. The browser explorer and this report communicate the same experiment at different levels of detail.

Why this question matters

A single overall consequence can be convenient, but it can hide how that label was obtained. Conversely, the most severe term across every transcript may come from a model that is not the representative coding transcript. Reviewing both views prevents a misleading impression that one summary is the only valid molecular description.

4. HG002 analysis: process and quality control

4.1 Define the scope before looking at consequences

The fixed interval was GRCh38 chr9:128,000,001–129,000,000, a contiguous 1 Mb region surrounding the Training validation teaching region. It was recorded before examining HG002 annotation consequences. This is a purposeful pilot interval, not a random genomic sample. Therefore its spectrum is descriptive of this interval and benchmark sample.

The callset was pinned to GIAB HG002 NIST v4.2.1 GRCh38, together with its matching benchmark_noinconsistent.bed. Tabix/HTSlib indexed extraction retrieved the interval while preserving the original VCF header and records. A full remote VCF download and full-file checksum are not claimed; acquired slices and indexes have their own SHA-256 hashes.

4.2 Establish an unambiguous allele identity

Multiallelic records were split into individual ALT alleles present in the HG002 sample genotype. Source IDs, original ALT indexes, coordinates and complete records were retained. Chromosome naming was reconciled from chr9 to 9 for Ensembl and reference compatibility. Symbolic alleles, breakends, spanning-deletion stars, unsupported sequence and alleles over 50 bases were outside the declared eligibility rules.

Each included reference allele was compared with the full forward-strand GRCh38 REF interval. Normalization used pysam 0.23.3 and embedded bcftools 1.21 with the official Ensembl release 116 chromosome 9 FASTA. Indels were trimmed and left-aligned against that sequence. Deduplication used chromosome, normalized position, REF and ALT together; sharing a coordinate alone was insufficient.

4.3 Handle coordinates and boundaries consistently

VCF positions are 1-based. BED and internal bin intervals are 0-based, half-open. A VCF record’s anchored REF span is [POS−1, POS−1+length(REF)). That complete span had to lie inside the chosen interval and a merged high-confidence BED region, both before and after normalization. An insertion is assigned using its reference anchor. A shifted allele falling outside those rules would be explicitly excluded.

4.4 Acquire authentic annotations safely

VEP REST requests used batches of no more than 100 alleles, with HGVS, MANE, canonical flags and transcript versions requested and all returned transcripts retained. There were 14 bounded batches, restricted to this pilot. Exact requests, untouched response bytes, timestamps, hashes, engine/service metadata where reported and input/reference/settings fingerprints were saved.

Response matching used verified echoed identity and normalized locus/allele representation, not array order. Missing, duplicate, unmatched or incorrect-build responses fail validation. Chunks resume only with matching fingerprints and raw hashes. A complete successful snapshot is promoted only after all inputs reconcile; the previous snapshot remains usable when acquisition fails. The database release was 116; a separate VEP engine version was not reported.

4.5 Compare transcript selection fairly

A representative was selected separately for every allele–gene pair with transcript rows: applicable MANE Select first, then canonical, then deterministic accession order. Ties at the preferred tier were counted and resolved deterministically. Consequence sets were compared regardless of term order. A “missed more-severe term” means another transcript of that same gene has a higher-ranked molecular term than the representative, using the pinned Ensembl 116 ranking.

Regulatory, motif and intergenic annotations were retained separately, rather than accidentally counted as transcript rows. Blank optional values mean “not reported”; no missing HGVS, gene symbol or transcript flag was invented.

5. Expanded results and their meaning

5.1 How much data was actually analyzed?

The final expanded run contains 1,307 distinct alleles: 1,076 single-base substitutions and 231 indels. All have valid VEP response objects. There are 38,589 transcript rows, and 22 alleles have no transcript overlap in the returned output. These counts measure different units and must not be interchanged.

5.2 What kinds of consequences were reported?

The largest provider-summary category is intron_variant, with 900 alleles. The run also includes 18 missense summaries, 19 synonymous summaries, 1 frameshift summary and 1 in-frame deletion summary. A rare severe-sounding molecular term is an annotation to examine, not a project diagnosis.

Why this matters: the spectrum describes how supplied benchmark alleles relate to the current gene models. It does not estimate disease prevalence, the frequency of these alleles in a population, or the accuracy of the original variant calls. A provider summary is computed across features; the selected transcript can legitimately have a different term.

5.3 How sensitive are results to transcript choice?

Consequence sets differ across transcripts in 1,081 of 2,170 pairs (49.8%). In 183 pairs (8.4%), the representative omits a more severe same-gene term found elsewhere. These percentages are strictly within-run annotation comparisons, not population estimates.

Practical interpretation: representatives support consistent reporting, but the full evidence remains necessary. The SPTAN1 case below demonstrates why a splice-related term on an alternative transcript should be read alongside the intronic annotation on the MANE representative.

5.4 Where do variants occur in the interval?

The interval contains 886,920 high-confidence bases out of 1,000,000. Counts are aggregated into forty fixed 25 kb windows. Unequal coverage means raw bin counts alone do not describe equal amounts of assessed sequence. Rates therefore use each bin’s clipped high-confidence bases. No zero-coverage window would receive a calculated zero-variant rate.

Why this matters: a bar can be low because fewer supplied alleles occur there, because the callable benchmark coverage differs, or both. These are descriptive observations from one selected interval; no disease-hotspot or regional-selection claim is made.

7. Dated clinical evidence overlay

The overlay uses the fixed ClinVar GRCh38 release dated 8 November 2026. All chromosome 9 records were queried by index to avoid relying on a small padded interval that might miss equivalent indel representations. The extract contained 204,568 records/ALT alleles; 326 were outside the declared sequence/50-base eligibility. Eligible alleles were reference-checked and normalized with the same tool and reference as HG002 before exact matching.

There were 116 exact matched HG002 alleles and 1,191 without an exact eligible match. Each match retained Variation ID, source classification summary, review status, condition names/identifiers, conflicts, original record and source link. Coordinate-only VEP co-location identifiers were not used as substitutes for exact matching.

8. Software, explorer and reproducibility

Separate acquisition from offline analysis

The project uses small Python entry points. Network acquisition is separate from reference validation, normalization, analysis and report generation. Normal report rebuilding uses a saved authentic snapshot and makes no network requests. JSON/TSV schemas document units, missingness, stable identities and the relationship between selected rows and raw output.

Training validation uses Python standard-library tooling. HG002 analysis pins pysam 0.23.3, with embedded bcftools/HTSlib 1.21. The optional 3D component bundles Three.js 0.180.0 and its MIT licence locally. The shareable HTML report embeds its styling and vector figures, so it can be copied independently of the project folder and opened without a server.

A simpler explorer for readers

The revised explorer defaults to an exact 2D position/count view. Selecting a type or consequence updates the view immediately; gene text updates live. A “What changed?” explanation identifies active filters and excluded alleles. A fixed count scale keeps filtered views comparable. The user then selects a 25 kb region and one allele, with plain-language consequence guidance before expandable transcript evidence. 3D remains optional, with a single restrained bar colour and a selected-region highlight rather than a rainbow that might imply clinical risk.

Filters only change the displayed subset of the saved experiment. They do not rerun VEP or alter the underlying result. Gene filtering is case-insensitive and accepts partial symbols or stable IDs. Consequence filtering uses the overall provider summary; individual transcript consequences remain visible as a separate concept.

9. Limitations and work not completed

  • Coverage: this is one preselected 1 Mb benchmark interval. It is neither whole-chromosome coverage nor a random genomic or population sample.
  • Offline chromosome annotation: not executed. The standard Ensembl 116 GRCh38 cache archive is 27,644,657,162 bytes compressed, exceeding initially available approximately 22 GiB before extraction and other storage. Docker’s daemon was unavailable, and no local VEP/cache was found.
  • Architecture: published release_116.0 images support linux/arm64 and linux/amd64. Architecture compatibility is available; storage and the operational engine/cache setup are the blockers.
  • Backend completeness: a full offline JSON Lines adapter, chromosome chunking/resume path and corresponding verification remain to be implemented after infrastructure is provisioned. The completed REST pipeline is deliberately bounded.
  • Release metadata: Ensembl database release 116 was reported; a separate VEP engine version was not.
  • Clinical evidence: the overlay is dated and retains source assertions. No formal clinical classification, patient outcome, diagnosis or comprehensive disease-specific interpretation is supplied.
  • Transcript models: differing annotations reflect current transcript structures/biotypes. A severe term on one alternative model is not proof that model is the most clinically relevant.
  • Performance and validation: timings are local observations. Browser checks are not a formal performance study or complete accessibility certification.
  • Rights and publication: data remain local. No GitHub push or deployment was performed. Upstream and third-party reuse terms must be reviewed before distributing raw snapshots or source datasets; no code licence is applied to them.

The HTML and PDF are explanatory summaries prepared for sharing. They contain selected observed results and source citations, rather than the complete benchmark or raw VEP/ClinVar datasets. This report does not claim NHS affiliation or clinical endorsement.

11. Conclusions

The completed work establishes an auditable annotation workflow from five training examples to 1,307 HG002 alleles in a fixed benchmark interval. It demonstrates, with authentic output, that transcript context materially changes the molecular annotation for many allele–gene pairs. A representative transcript is useful for consistent reporting, but its result should remain linked to the other transcript evidence.

The experiment also demonstrates the value of exact allele matching, explicit coverage and missingness, and saved source provenance. The ClinVar overlap provides dated assertions for review without converting predictions into diagnoses. The appropriate next analytical step is provisioned offline scaling with the same QC discipline; the appropriate next interpretive step is scoped, condition-specific evidence review.
